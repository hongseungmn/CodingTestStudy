## 1. 시간 복잡도 (Time Complexity)와 문제 제약조건 읽기

코딩테스트 문제를 접했을 때 **가장 먼저 확인해야 하는 것은 입력값 $N$의 범위(제약조건)**입니다.
컴퓨터는 대략 **1초에 약 $10^8$번 (1억 번)의 기본 연산**을 수행할 수 있다고 가정합니다.

| $N$의 크기 | 허용 가능한 시간 복잡도 | 적합한 알고리즘 / 자료구조 |
| :--- | :--- | :--- |
| $N \le 10 \sim 12$ | $O(N!)$ 또는 $O(2^N)$ | 순열, 완전 탐색, 백트래킹 |
| $N \le 20 \sim 25$ | $O(2^N)$ | 비트마스킹, DFS/BFS 완전 탐색 |
| $N \le 500$ | $O(N^3)$ | 플로이드-워셜, 3중 반복문 |
| $N \le 2,000 \sim 5,000$ | $O(N^2)$ | 2중 반복문, 단순 DP, 삽입/선택 정렬 |
| $N \le 100,000 \sim 1,000,000$ | **$O(N \log N)$ 또는 $O(N)$** | 정렬, 힙, 이진탐색, 스택/큐, 투포인터, 해시 |
| $N \ge 10,000,000$ | $O(N)$ 또는 $O(\log N)$ | 단순 선형 순회, 이진탐색, 수학적 공식 |

> **💡 교수의 팁:** $N = 100,000$인데 $O(N^2)$인 중첩 루프를 쓰면 약 $10^{10}$번 연산이 되어 바로 **시간 초과(Time Limit Exceeded)**를 받게 됩니다. $N$을 보고 목표 시간 복잡도를 먼저 결정하세요!

## 2. 배열(Array) vs 동적 배열(ArrayList) vs 연결 리스트(LinkedList)

Java에서 가장 기본이 되는 선형 자료구조 3가지의 동작 원리와 시간 복잡도를 정확히 알아야 합니다.

| 연산 | Array (정적 배열) | `ArrayList` (동적 배열) | `LinkedList` (이중 연결 리스트) |
| :--- | :--- | :--- | :--- |
| **인덱스 접근 (Random Access)** | $O(1)$ | $O(1)$ | $O(N)$ (처음부터 탐색) |
| **맨 뒤 추가 (Append)** | 불가 (크기 고정) | Amortized $O(1)$ | $O(1)$ |
| **맨 앞/중간 삽입·삭제** | 불가 | $O(N)$ (데이터 쉬프트 발생) | $O(1)$ (해당 노드를 이미 알고 있을 때) / 노드 찾는 시간 포함 시 $O(N)$ |
| **메모리 구조** | 연속된 물리 메모리 블록 | 연속된 물리 메모리 블록 | 힙(Heap) 곳곳에 흩어진 노드 참조 |
| **CPU 캐시 지역성 (Cache Locality)** | **매우 높음** (속도 빠름) | **매우 높음** (속도 빠름) | **낮음** (포인터 체이싱으로 인한 캐시 미스) |

### 🔍 ArrayList의 Amortized $O(1)$ (분할 상환 시간 복잡도)란?
- `ArrayList` 내부에는 실제 Java 기본 배열(`Object[] elementData`)이 들어있습니다.
- 배열이 꽉 찼을 때 `add()`를 호출하면:
  1. 기존 크기의 보통 **1.5배**에 달하는 새로운 배열을 할당합니다 (`grow()` 메서드).
  2. 기존 요소들을 새 배열로 복사합니다 ($O(N)$).
- 하지만 이 크기 증가 작업은 자주 발생하지 않고 가끔만 발생하므로, $N$번 삽입하는 전체 비용을 $N$으로 나누면 **평균적으로 1회당 $O(1)$**로 수렴합니다. 이를 **분할 상환(Amortized)** 분석이라고 부릅니다.

### 🔍 코딩테스트에서 `LinkedList`를 잘 안 쓰는 이유
많은 입문자들이 "삽입/삭제가 빈번하면 무조건 LinkedList다"라고 외우지만, 실전에서는:
1. 삽입/삭제할 위치까지 찾아가는 데 이미 $O(N)$이 듭니다.
2. 각 노드마다 데이터 외에 앞/뒤 포인터(`prev`, `next`) 객체 오버헤드가 발생합니다.
3. 메모리가 물리적으로 불연속적이어서 CPU 캐시 적중률이 떨어집니다.
따라서 양방향 큐/스택 기능이 필요할 때는 `LinkedList`보다 **`ArrayDeque`**를 사용하는 것이 정석입니다.
